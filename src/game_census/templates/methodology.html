Source, scope & interpretation

Know what
you're looking at.

A useful statistic includes its limits. Here is how this instance turns Steam responses into player activity.

01—06
01

Players means concurrent activity.

The Steam current-player endpoint supplies the number of users currently active in an app. Game Census records the validated count and the time its collector received the response. Steam does not supply an observation timestamp for this method.

These are Steam-reported concurrent players, not unique daily players, owners, sales, or verified humans. A valid zero is a real observation. A failed request never becomes zero.

02

Freshness is visible.

A count is fresh at the time of the page read when its age is no more than {{ freshness_multiplier }} times the app's configured interval. Older counts are labeled stale and shown as last observed. Fresh receipt does not prove that Steam's own underlying value was just updated.

Collection outcomes remain separate from the last valid count. An app without a successful observation shows an unavailable value, not an invented estimate. Page loads and stored-data refreshes read local storage. The explicit Search Steam and Refresh Steam charts forms make bounded requests through the collection ledger.

03

History begins here.

Game Census retains its own observations. There is no SteamDB import or fabricated history before tracking began. The observed 24-hour peak is the highest received count in that period. Highest recorded is the largest count recorded by this instance since tracking began.

Neither is a game's all-time Steam record. Missing samples may hide a higher peak. Every chart reports its observation count and time coverage.

04

Gaps stay gaps.

The average observed CCU is a time-weighted average. Each observation contributes its value until the next observation, the window end, or {{ gap_multiplier }} times its configured interval—whichever arrives first. Uncovered time adds no value and no weight. An average with no covered time is unavailable.

Coverage is covered seconds divided by requested seconds. It includes missing time before tracking began. Expected samples use the configured cadence within enrolled time; manual runs do not imply that a scheduler is active. The maximum gap identifies the longest uncovered span in the requested window. Growth compares average observed CCU across adjacent equal windows and requires at least {{ (minimum_coverage_ratio * 100)|round(1) }}% coverage in each. A zero baseline has no percentage growth.

Charts connect nearby observations and break across cadence-capped gaps. Use the observation table for exact samples. Times and half-open window boundaries are UTC. Charts allow up to {{ max_history_days }} days and {{ max_points|number }} returned points. Longer series use UTC buckets that retain the original first, last, minimum and maximum observations plus gap boundaries. Window statistics use all retained samples within the source-read bound. The raw API returns each sample or rejects an oversized request; explicit auto resolution returns its bucket summaries. Neither mode fabricates samples.

05

Discovery and tracking have separate scopes.

The catalog contains apps discovered through Steam's public Store search, global charts, and the optional GetAppList game catalog API. Public search uses US / English game listings and imports at most 50 results per request. A completed keyed scan means the API's game-only cursor reached its end at the displayed time; availability and Store contents can change. Partial discovery is labeled. Absence does not imply removal.

Discovery never starts player tracking. The tracked list and player API retain all enrolled apps and their history. A known but untracked app has no local player history.

Most played uses Steam's global top-100 app entries and reports concurrent players plus Steam's Peak Today, distinct from local observed peaks. Top sellers are revenue ranks: trailing 24-hour revenue with extra weighting for the latest three hours. They do not report copies sold or sales amounts. Package and hardware entries are excluded while original ranks remain intact.

Trending compares concurrent counts in the two latest distinct-time most-played captures, restricted to apps present in both. Positive absolute gains determine the order; percentages use the earlier count and are unavailable when it was zero. This is a changing top-100 cohort, not a Steam-wide growth ranking. Capture timestamps describe receipt; Steam may cache its underlying charts.

06

Independent, with explicit collection.

This interface reads stored observations through the versioned read API. The OpenAPI contract describes its routes and bounds. GET pages and read APIs never collect from Steam. Explicit same-origin forms and operator commands perform bounded collection. Successful source captures, independent failures, request quotas and cooldowns are retained. Operators can activate bounded scheduled runs after acknowledging a successful watched manual run with the same collection plan. Installation and website restart do not start a collector. Every retry and probe shares the durable request budget; missed scheduled slots remain gaps.
